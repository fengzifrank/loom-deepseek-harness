# 一家叫 Loom 的智能奶茶店（漫画版）

> 8 幅漫画讲清 Loom 框架的核心心智模型。奶茶的行话天生就是软件的行话：**配方标准化 = 契约；换谁来摇味道不变 = 实现可替换；一条大街很多家店 = 插件生态。**
> 图由 AI 生成（MiniMax image-01-live · 漫画风格），题注为人工撰写。配合[图解手册](diagrams.zh.md)（13 张精确架构图）与[学习指南](learn.html)食用更佳。完整 15 章版见[《智能奶茶店经营手册》](harness-book.zh.html)。

---

## 第 1 幅 · 意图 vs 流程

![第1幅 意图 vs 流程](img/comic/01-intent-vs-process.jpg)

左边是传统软件的世界：用户拿着写死步骤的"流程卡"亲自调茶，茶洒了一地——**App 本质上是一个提前冻住的 Workflow**。右边是智能奶茶店：你只说一句"一杯少糖去冰的乌龙奶茶"，操作台自己知道怎么做。

> 对应术语：**意图驱动**——用户表达目标，编排交给 agent。

---

## 第 2 幅 · 配方卡 = 签给机器的承诺书

![第2幅 配方卡即承诺](img/comic/02-menu-contract.jpg)

菜单墙上每款饮品的配方（茶底几克、糖几分、冰几块），是**签给机器看的承诺**（不是给人看的广告）。三台机器按配方卡干活：**留样秤**逐项核对出品（内核输出校验）、**盘点机器人**按规格登记入库（类型化客户端）、**打包机**按规格分格装箱（Code Mode 调用）。糊弄配方卡 = 拆掉质检机——那杯茶坏了没人拦，仓库的账全是错的。

> 对应术语：**tool schema / canonical JSON**——一次声明，处处机器可验证。

---

## 第 3 幅 · 三个出口，一份数据

![第3幅 三个出口一份数据](img/comic/03-three-outlets.jpg)

同一杯茶，三种去向：**仓库货架**登记的是素颜事实（成分数据，永远不化妆）；**讲解词**把数据讲成人话给模型听；**展示冰柜**把数据装扮成精美陈列给人看；**打包机**给程序消费，零化妆。想换冰柜陈列样式？动冰柜就行，仓库里的账一个字不用改——改版式永远不需要重新做那杯茶。

> 对应术语：**canonical value（素颜数据）· output.render（给模型）· UI 卡片（给人）**。

---

## 第 4 幅 · 档案室：唯一事实来源

![第4幅 档案室](img/comic/04-archive-room.jpg)

店里所有发生的事——顾客点了什么、奶茶师每一步做了什么、每杯的留样数据——按页码记进一本**永不涂改的厚账本**。六个部门全部读这同一本：奶茶师做下一杯前**重读账本**（而不是凭记忆）、取餐屏直播新页、安全局审计、老板抽数据做复盘。奶茶师没有"记忆"，记忆是每次从账本**现算**的——所以永不记错历史、重启不失忆。

> 对应术语：**会话日志（session log）· append-only · deriveMessages**。

---

## 第 5 幅 · 小纸条禁令

![第5幅 小纸条禁令](img/comic/05-no-side-notes.jpg)

有人偷偷递小纸条（"这杯多放珍珠别记账"）？奶茶师摆手拒绝，指指玻璃罩下的账本。**奶茶师只许看账本上写的东西。** 任何想影响模型的内容——注入的记忆、插件的附言、工具的补充——必须先写成账本的一页，再进入下次阅读。为什么这么死板？因为如果奶茶师看了账本之外的信息，半年后重放账本，就还原不出她当时真实看到的世界——"回放 = 事实"这座大厦会瞬间塌掉。

> 对应术语：**model-visible ⟺ logged**（模型可见 ⟺ 已落日志）——框架里有运行时断言盯着这条军规。

---

## 第 6 幅 · 经理审批：不在场 = 拒绝

![第6幅 经理审批](img/comic/06-approval-desk.jpg)

封一杯茶不用请示；但要**动真格**（改会员卡储值、动账上的钱）？托盘必须端到**经理的审批台**前等按钮。三条铁律：审批在**执行之前**（不是事后追认）；经理五分钟不在 = **自动拒绝**（fail-closed——错动一次账的损失远大于错拒十单的麻烦）；两张审批卡只认先到的那张。

> 对应术语：**approval（tools/pre-execute 裁决）· fail-closed · 幂等重发**。

---

## 第 7 幅 · fork：复印账本，不是重摇一遍

![第7幅 fork 复印](img/comic/07-fork-photocopy.jpg)

"刚才那杯糖放错了，从加糖之前那步重新来"怎么实现？**复印账本的前半本，放到一张新吧台上**——新奶茶师翻开复印件，看到的进展和原来一模一样，直接从那一步继续。那杯茶不用重摇（工具不重跑，因为账本上记着每一步的留样结果）；原账本一页不动；会员账户里的钱也不会倒带——fork 是对话的分叉，不是时光机。切复印点必须选在"账目两清"的回合边界，半截回合的账复印出来是自相矛盾的。

> 对应术语：**sessions.fork（在 turn 边界分叉）**。

---

## 第 8 幅 · 模块化操作台：一切皆插件

![第8幅 模块化操作台](img/comic/08-modular-kitchen.jpg)

这家店最狠的设计：煮茶机、封口机、小料台、**连"怎么摇茶"的操作流程本身**，都装在带把手的模块箱里，整体可换。今天换新煮茶机（换模型）、明天换冰柜品牌（换持久化）、后天连制茶班组都换掉（换 agent 循环）——墙上的配方卡（契约）和账本（事实）一个字不用动。**店规与承包分离**，这就是"没有特权内核"。一条大街上很多家奶茶店都这么开——同标准插座，家家做出自己的风味。

> 对应术语：**一切皆插件 · capability seam（契约/实现/消费分离）**——连 agent-loop 都是插件，是它区别于"焊死内核"产品的护城河。

## 一页看懂：故事 ↔ 术语对照

| 奶茶店 | 框架术语 | 一句话 |
|---|---|---|
| 配方卡 | tool schema | 签给机器的承诺，糊弄 = 拆质检 |
| 留样秤 | 内核输出校验 | canonical JSON 逐字段验 |
| 仓库登记本 | canonical value | 素颜数据，永不化妆 |
| 讲解词 | output.render | 给模型的人话，现场生成 |
| 展示冰柜 | UI 卡片 | 给人的妆容，纯函数可回放 |
| 打包机 | Code Mode / 类型化客户端 | 给程序的裸数据 |
| 档案室 | 会话日志 | 唯一事实，append-only，seq 连续 |
| 奶茶师重读账本 | deriveMessages | 上下文是投影不是存储 |
| 复印前半本 | sessions.fork | 从任意 turn 边界分叉，不重跑 |
| 经理按按钮 | approval | fail-closed，超时 = 拒绝 |
| 小纸条禁令 | model-visible ⟺ logged | 回放可信的命根子 |
| 承包位 | 插件 | 连 agent-loop 都可换 |
