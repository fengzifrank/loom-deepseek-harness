一、Loom 是什么？

三十秒版本。

传统 Web 框架（FastAPI / Express / Next）的原子是「请求 → 处理 → 响应」。智能体应用需要更大的原子：持久会话。Loom 把会话事件日志变成应用的唯一事实来源——模型上下文、界面、审计、评测，全部是同一份日志的投影。

❌ 传统「Web + AI」四不像
  • AI 被关在聊天框里，只会出建议
  • 改数据要人复制粘贴
  • 刷新即失忆，无法审计
  • 地图/图表和 AI 零连接
✅ Loom 形态
  • agent 通过工具直接操作业务数据
  • 写操作可挂人工审批闸门
  • 每个会话可回放、可分叉、可评测
  • 前端是事件流的实时投影
一句话：不是「给 Web 应用加个 AI 功能」，而是让智能体运行时成为应用的操作系统，Web 界面只是它的一个观察窗口。

二、为什么需要它？

request/response 范式的三重断裂，与业界三条独立线索的汇聚。

断裂传统范式智能体应用的真实需求
时间尺度请求毫秒级生命周期一个回合几十秒到几十分钟，含工具执行与人工审批——刷新页面不能杀死任务
状态归属无状态，状态是应用的附带品模型上下文是连续的、必须可完整重建的核心状态
权力模型auth 回答「谁能调接口」要回答「这个具体动作要不要人批准」——工具级、参数级、预算级，且必须留痕

业界三条线索，同一个方向

Temporal · 持久执行

事件历史 + 确定性重放 = 免费检查点。Loom 的会话日志天生如此，且更严格：模型可见 ⟺ 已落日志。

Phoenix LiveView · 服务端状态

证明了「UI 不拥有状态、只做投影」。Loom 投影的是带序号的事件流，断线重连 = ?since=seq 续传，LiveView 的重连难题自然消失。

Generative UI · 工具驱动界面

界面动作来自工具调用。Loom 走确定性路线：工具返回结构化数据 + 渲染意图卡片，回放逐像素重现。

三、核心概念（大白话版）

六条公理，每条都能在 白皮书 里找到源码级出处。

1️⃣ 一份声明，三张面孔

工具声明 → 模型可调用 + HTTP 端点 + 类型化客户端。像 FastAPI 的装饰器同时给你路由、校验和文档。

2️⃣ 会话记录即契约

Transcript is the contract。审计、调试、评测、分叉——全是读日志，不需要第二套系统。

3️⃣ UI 是投影

前端不拥有业务状态。刷新 = 重放，断线 = 按 seq 续传，多端 = 同一日志的多个投影。

4️⃣ 能力三件套

契约 / 实现 / 消费分离。换模型、换沙箱、换持久化后端，模型侧的契约纹丝不动。

5️⃣ 权力走口子

干预执行只有固定的拦截点（审批、策略、预算），没有后门；想影响模型看到的内容，唯一通道是写日志。

6️⃣ 一切可组合

应用 = 一组插件按层序组合，热插拔、无特权内核。站在 DeepSeek Harness 微内核之上。

声明工具：一份声明，三张面孔

import z from '@deepseek-ai/schemastery'
import { defineApp } from '@loom-sdk/web'

const app = defineApp('my-app', { model: 'deepseek-v4-flash' })

// ① 工具：模型可调用 + ② 自动获得 HTTP 端点 + ③ 前端类型化客户端
app.tool('query_land_types')
  .input({ region: { type: 'string', description: '村庄名（可选）' } })
  .output(z.object({ total: z.number(), items: z.array(z.object({ name: z.string() })) }))
  .card('generic', { title: '地类面积查询' })   // UI 渲染意图
  .http('GET')                              // → GET /~loom/api/query_land_types
  .execute(async (args, exec) => {
    // args.region 的类型由 input 字面量推导（string | undefined），内核已校验——
    // 不再需要手工 typeof 检查；output 写 z.object，required 由可选性推导。
    return landTypes.query(args.region)   // 只返回 canonical JSON
  })

六、五层架构

Loom 不与 DeepSeek Harness 并排造轮子——它站在内核之上，只补声明式体验层。

L5
你的应用业务工具 · persona · 投影 · 页面（如 examples/gis）
L4
投影与客户端层useAgentSession · useProjection · SSE 协议（seq/since/白名单）· 类型化客户端
L3
声明层（Loom 本体）defineApp · tool · agent · projection · policy · http —— 声明编译为插件与路由
L2
DeepSeek Harness 内核会话日志 · agent-loop · 工具管线 · LLM 适配 · 审批/权限 · 多智能体 · 持久化
L1
Cordis 框架基座IoC + 类型化事件 + 可逆效果（注册即资源，卸载即回收）
依赖铁律：Loom 只依赖内核的 Service Definitions（ctx.tools / ctx.agents / ctx.webServer…），永不绑定具体实现——所以模型、沙箱、持久化后端随时可换。

七、一条消息的一生

理解这个流程，就理解了 Loom 的一切。

1
你说了一句话前端 POST 到 /~loom/agents/data-analyst/sessions/:id/messages——前端只是传话筒
2
进入会话收件箱消息作为事件写进 append-only 会话日志，永不丢失
3
agent 开回合上下文从日志现算（deriveMessages）→ 打给模型 → 模型决定调用哪些工具
4
工具经过策略口子allow 放行 · deny 拒绝 · approve 弹审批卡等人工裁决（超时即拒绝，fail-closed）
5
结果回写日志工具结果以带序号（seq）的事件落盘——这是唯一事实
6
前端实时投影SSE 直播线上每来一条事件，聊天流/饼图/地图/任务面板各自认领自己关心的
7
回合结束，一切可回放任意时刻拖动调试滑块回到任意 seq，或从该点分叉出新会话

九、进阶：审批治理与时间旅行

这两组能力是 Loom 区别于「聊天 SDK」的分水岭。

审批闭环（fail-closed）

写类工具声明为 approve 后：模型调用 → 策略口子拦截 → SSE 推送审批卡片到页面 → 人点「允许/拒绝」→ 工具继续或失败。无人应答 5 分钟自动拒绝；每次裁决都有审计记录。

时间旅行调试器

页面的「回放调试」面板：完整事件流列表 + 滑块定位任意 seq + 该时刻的应用状态快照 +「从此点分叉」生成新会话。线上出问题，拖回去看当时模型看到了什么——因为请求可从日志逐字节重建，这不是模拟，是事实重放。

试试：先正常跑一次分析，然后打开调试面板拖到第一个 tool/call 之前——你会看到饼图"缩回"未渲染状态，因为投影是纯函数，给它哪个区间的事件，它就呈现哪个时刻的世界。

十、类型化客户端与评测

第三张面孔长出代码，真实会话日志变成回归测试集——M4 收官路线图。

loom client：生成物即前端 SDK

pnpm loom client 读取应用声明，生成 src/loom.client.ts（自动生成，勿手改）：工具函数的入参类型来自 InferToolArgs、返回类型来自 InferToolOutput——改声明后重新生成，所有调用点在编译期报错；agent id 是字面量联合类型，拼错即红；streamEvents 把 SSE 包成 AsyncIterable。

// src/loom.client.ts（pnpm loom client 生成，勿手改）
export type GisQueryLandTypesArgs = InferToolArgs<{ region: { type: 'string', … } }>
export type GisQueryLandTypesOutput = InferToolOutput<{ … totalAreaSqm: number; items: Array<{…}> … }>

export const loomTools = {
  /** GET /~loom/api/gis_query_land_types */
  async gis_query_land_types(args: GisQueryLandTypesArgs = {}): Promise<GisQueryLandTypesOutput> { … },
}
// 调用端全程有类型：region?: string；返回 totalAreaSqm: number（真实值 57351531.17）
const r = await loomTools.gis_query_land_types({ region: '连河村' })
复制

loom eval：transcript 即评测集

真实跑出的会话日志就是评测夹具：loom eval --slim <session.jsonl> 把日志折叠成精简夹具（assistant/chunk 增量折叠、turn/tool/approval 原样保留），evals/*.eval.ts 里声明断言，pnpm eval:gis 纯本地重放——零网络、零 key。

// evals/approval-allowed.eval.ts（对真实会话日志的纯重放断言）
export default defineEval({
  name: 'approval-allowed',
  fixture: 'fixtures/approval-allowed.jsonl',  // 真实审批链日志的精简投影
  assert(ev) {
    ev.expect.toolCalled('gis_update_land_note')
    const flow = ev.expect.approvalFlow()          // asked → decided 顺序
    if (flow.outcome !== 'allowed-once') throw new Error('…')
    ev.expect.turnEnded('completed')
  },
})
复制
价值一句话：CI 里零网络、零 key 地重放真实智能体行为——审批闭环、委派链、webhook 入口的行为回归从此免费，评测集还随真实使用自动生长；配 loom client 新鲜度门（生成后 git diff --exit-code），声明与生成物永不漂移。

十二、记忆、多用户与路径记忆

框架的三块"产品级"能力：跨会话不失忆、多人互不干扰、失败时能召回历史成功路径。

记忆系统：三层结构（M7）

层是什么入口
会话内记忆会话日志 + 压缩（compaction）+ 持久化——重启可恢复、可分叉内核原生
跨会话语义记忆mem0 式两阶段（提取 → ADD/UPDATE/DELETE/NOOP 决策）+ SQLite FTS5 检索，按用户隔离app.memory()
路径记忆带验证的执行序列——失败时召回重用（见下）memory: { paths: true }
app.memory({ extraction: { maxPerTurn: 3 }, recall: { topK: 5 } })
app.agent('data-analyst', { memory: true, ... })   // 提取花 token，默认关、显式开
复制

实测闭环：告诉 agent"请记住我偏好中文报告、单位用万亩"→ 回合结束自动提取落库 → 新开会话问偏好 → 历史记忆以 form:'recall' 事件注入 → 回答带着偏好。前端有 MemoryPanel（搜索/编辑/删除），模型也有 memory_search / memory_write / memory_forget 工具（走策略管线，forget 可配审批）。

多用户：匿名 + 本地账号（M7）

默认双模式：匿名（浏览器自动生成 UUID，零门槛）+ 本地账号（用户名密码，scrypt 哈希 + HMAC token，零依赖）。会话、审批、记忆全部按用户隔离——别人的会话连"存在"都不会泄露（404）。前端一个 hook 搞定：

const { user, login, register } = useLoomAuth()
复制

路径记忆：走通过的人留下路（M8）

语义记忆记"事实"，记不住"怎么做成过一件事"。路径记忆补这一层——一个带工具图签名的执行序列，失败时自动召回：

1
任务失败turn/end error/blocked 触发（只有 paths:true 的 agent 才积累路径）
2
检索历史路径FTS 按任务目标命中同用户的历史成功路径（含被拒路径，降权）
3
注入"待重验路径"防注入框明示：先重跑只读步骤验证数据仍在，才可复用
4
重验回写成功 confidence +0.1、verified_at 刷新；失败 ×0.5；连续失败软删——路径会"风化"
这是"能量竞争"的最小实现：新路径与旧路径按验证新鲜度竞争，无人维护的路自动荒废。设计细节见 docs/path-memory.zh.md，记忆全景见 docs/memory.zh.md，多用户见 docs/auth.zh.md。

十三、FAQ

Loom 和「把 Web 服务写成插件给 harness 用」是一回事吗？

方向对一半。精确说：独立的 Web 服务层消失了——它的执行职责（业务逻辑）内化为 harness 插件（工具/智能体），对外职责由 webserver 与自动生成的路由承担，页面职责交给前端投影。harness 不是你接入的平台，而是应用 rewritten 之后的操作系统。

和 Vercel AI SDK / Mastra / LangGraph 什么关系？

它们分别解决「渲染流」「跑 agent」「图编排」。Loom 解决的是以 agent 为中枢构建整个 Web 应用：持久会话、审批治理、投影协议、声明式三面孔。底层执行与事务性由 DeepSeek Harness 内核提供，可与其他框架的能力互补而非互斥。

必须用 DeepSeek 的模型吗？

不。内核的 LLM 层是适配器体系（OpenAI 兼容、Anthropic 等多协议），换 provider 不改一行应用代码。示例默认 deepseek-v4-flash 是因为性价比。

我的前端必须用 React 吗？

不。前端与框架之间是纯协议（HTTP + SSE），官方提供 React hooks 参考实现；Vue/Svelte/原生 JS 都能接。

有记忆系统吗？多个用户怎么隔离？

M7 起有了，而且是声明式的。三件事一起交付：① 重启不失忆——会话登记在 sidecar 索引，服务重启后同 sessionId 惰性 resume，历史完整重放、直接续聊；② 多用户——app.auth() 一行声明，匿名 UUID 即开即用，本地账号注册/登录（scrypt + HMAC token，零第三方依赖），会话与记忆按 userId 隔离（他人的 → 404 不泄露存在性），审批仅属主；③ loom memory——app.memory() + agent 级 memory: true（提取花 token，默认关）：每个完成的 turn 后两阶段提取（候选 → 对照 FTS 相似 → ADD/UPDATE/DELETE/NOOP，mem0 v2 风格），会话首条消息时 FTS top-K 召回注入（防注入框 + form:'recall'）；存储是 .loom/memory.db（node:sqlite FTS5，零新依赖，中文 bigram 分词），另有 memory_search/write/forget 三个模型工具与记忆面板。不想用内置的？mem0 经 Python 桥、外部 MCP 记忆服务、内核 session-query 全历史检索三条适配配方见 docs/memory.zh.md；认证细节与生产反代建议见 docs/auth.zh.md。

审批卡刷新页面就丢了？

当前版本未决审批在超时后自动拒绝（fail-closed），不丢安全性只丢便利性；持久化审批队列在路线图中。

已有 FastAPI 服务怎么接入？

两条路，都走 OpenAPI。① 把 FastAPI 的 API 变成 Loom 工具：FastAPI 自带 /openapi.json，loom import-openapi http://127.0.0.1:8000/openapi.json --base http://127.0.0.1:8000 生成 loom.openapi.ts，在 loom.app.ts 里一行 registerImportedTools(app)——外部 API 立即获得模型面孔 + 策略/审批（写操作自动获得 approve 建议）。② 把 Loom 应用交付给 OpenAPI 生态：loom openapi 导出确定性 OpenAPI 3.1.0 文档（或直接消费运行时 GET /~loom/openapi.json），任何代码生成器/网关都能接。导入侧诚实降级：Loom DSL 覆盖不了的 schema 部分降级为 json 并留 // WARN(openapi-import) 注释，绝不静默出错。

企业老系统怎么接入？

按"老系统还剩什么"分三路，可以混用。① 有 OpenAPI 文档：一条 loom import-openapi <url> --base <url> 生成工具声明，loom.app.ts 里一行 registerImportedTools(app)——模型面孔 + HTTP 面孔 + 策略/审批白得；文档覆盖不了的 schema 部分诚实降级并留 // WARN(openapi-import) 注释，绝不静默出错。② 接口在跑但没写进文档：手写一个十几行的包装工具（fetch + 注入认证 + 如实声明 output），治理与回放照常生效。③ 连 API 都没有、只剩数据库：用 node:sqlite 以 readOnly: true 直连老库做对账审计（框架要求 Node ≥22.13，node:sqlite 免 flag）。写操作（如下单）在 policy 里配 approve 即得人工审批卡——真实改老系统数据，被拒不编造成功，全程落会话日志可回放。完整示例见仓库 examples/legacy-erp（含决策表、启动步骤与演示话术）。

有真实老系统的对接案例吗？

有，而且是双案例。① 真实项目实录（examples/fastapi-admin）：开源项目 FastapiAdmin（1k★，FastAPI + SQLAlchemy + Redis 的企业后台）在本机原样跑起来，一行不改接进 Loom——loom import-openapi 从它的 /openapi.json 生成 15 个用户域工具（诚实降级 493 条 WARN），JWT 登录用一个 fetch 包装桥接（token 过期模型自动 legacy_relogin 自愈，无需重启），创建/修改/删除用户全部走审批卡真实落库；这次对接还反过来修了框架：FastAPI 的 Optional[X] 可空联合（anyOf:[T,null]）从降级改为忠实转换。② 离线模拟（examples/legacy-erp）：模拟 2018 ERP 覆盖第三路（只读直连库），CI 里随时可跑。真实案例讲"活系统怎么接"，离线案例讲"三路全走一遍"。

业务逻辑想用 Python 写怎么办？

用 Python 工具桥（M6）：内核保持 TypeScript，Python 成为一等工具作者语言。写一个普通 Python 脚本（如 py_tools.py），用 @tool 装饰器声明工具（类型注解自动推断 JSON Schema，pydantic 可用则增强），末尾 run() 进入 stdio 协议主循环；loom.app.ts 里一行 app.python({ command: 'python py_tools.py' }) 把清单注册为模型可见的代理工具——策略/审批照常生效。异常转结构化错误（模型可自行纠正），进程崩溃自动重启（上限 3 次 fail-loud），loom_py 包纯标准库零依赖（python -m loom_py.selftest 自测）。注意两点：工具函数里 print 会污染协议（调试写 stderr）；v1 只有模型面孔（无 .http()/客户端生成）。完整指南见 docs/python-tools.zh.md。

Windows 能开发吗？

能。本项目的参考应用就是在 Windows 上开发验证的。需要 Node ≥24 与 pnpm（corepack enable）；Python 工具桥另需 Python 3.10+（loom_py.run() 已强制 UTF-8 管道，中文往返无损）。

Loom 与 dsh-plugin 生态什么关系？

既是消费者，也是生产者（M8 起）。消费侧：Loom 的组合直接用内核官方插件——会话历史查询（dsh-session-query-sqlite + dsh-tool-session-query，模型能真实调用 session_search 翻自己的历史会话）、生产静态服务（dsh-host-frontend-static，loom start 的同端口 SPA fallback，替代了早期手写实现）。生产侧：两个原内嵌能力抽成了独立插件包——dsh-python-tools（Python 工具桥，任何 harness 应用都能用，不必装 Loom）与 dsh-web-approval-answerer（SSE 审批 answerer：审批卡推送/断线重发/并发 409/超时 fail-closed）。生态扫描结论：记忆与 Python 桥、人审 answerer 均无同构现成件，这两包各自填补空白。供应链纪律：所有 @deepseek-ai/* 依赖钉精确版本（npm latest tag 普遍指向旧版 0.0.1-rc.x，浮动解析会静默降级）；升级必须整批同升 + 全量 e2e。详见 docs/plugin-ecosystem.zh.md。
